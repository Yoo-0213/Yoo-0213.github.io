协议架构

  • 系统架构

    一个典型的 AXI 总线网络可以由多个 Master 、Slave 设备通过 Interconnect 进行连接；亦或者是模块之间直接使用 AXI 总线进行连接





  • 传输结构


    如上图所示，为 AXI 协议的接口架构，总共有 5 个通道，分别是：

    • 写地址通道
    • 写数据通道
    • 写响应通道
    • 读地址通道
    • 读数据通道

    地址通道是用来告知 Slave 端本次传输的控制信息，而数据通道则是 Master 端和 Slave 端之间的数据交互

    • 写数据通道用来传输数据给 Slave 端，在写事务中，Slave 用写响应通道来告知 Master 端本次传输的接收情况
    • 读数据通道则是Slave 把数据以及接收情况告知给 Master 端

Valid & Ready

所有通道都使用 Valid 和 Ready 信号来将 Master 、Slave 端握手传输数据、地址以及控制信息等；数据的传输只发生在两个信号都为高电平时
以下为 AXI 协议中的 2 种握手方式

  1. Valid 在 Ready 之前拉高

    源端在 T1 时刻已经把需要传输的数据准备好了，而目的端由于其他原因导致只能在 T2 时刻才可以接收数据
    那么这时候源端就==需要数据一直保持不变直至目的端接收完数据==才可以发生变化

    🔴Valid 的拉高不能依赖于 Ready，在设计中，源端的 Valid 和其他传输的数据不能等 Ready 有效时才输出，而是先输出直到目的端接收到数据后才能发生变化

    🔴但允许目的端的 Ready 依赖 Valid，目的端 Ready 的产生逻辑可以在收到 Valid 之后且内部逻辑是空闲的，这时候才拉高 Ready 信号

  2. Valid 在 Ready 之后拉高

    目的端在 T1 时刻就准备好接收数据了，但是源端在 T2 时刻才把数据发送出去
    还有一种是 Valid 和 Ready 信号都刚好在同一时刻拉高








Burst Length

Length 表示的是在==传输事务中（Transaction）中数据传输（Each Transfer）的次数，即一次事务中数据传输的数量，传输总数 = AxLEN + 1==
以下为 AXI 传输长度的规则要求：

  • 对于 Fixed 突发类型，Length 最大支持到 16
  • 对于 Incr 突发类型，Length 支持 1 ~ 256，而 AXI3 协议仅支持 1 ~ 16
  • 对于 Wrap 突发类型，Length 必须是 2/4/8/16
  • 🔴传输事务禁止超过 4KB 地址边界（尚不理解）
  • 不允许提前终止传输事务

需要注意的是，如果使用的 ip 对 Max_Transaction_Bytes 有限制，则需要根据 AXI 总线的数据位宽计算，单个事务允许的最大 Burst Length

举例：
如果 IP 限制 Max_Transaction_Bytes 为 4KB ，AXI 总线位宽是 256bit（32B） ，在每个 Beat 均传输完整数据的情况下
最大传输总数 Burst Length = 4KB / 32B = 128






Burst Size

Size 表示的是==每次数据传输（ Each Transfer ）的最大字节数==

  • 对于读事务来说，Size 表示的是每次读数据必须有效的字节数；
  • 对于写事务来说，Size 表示的是写数据中有多少个字节被允许使用，而 write strobes 表示的是具体哪些字节是有效的





Burst Type

Burst 表示的是==事务传输中（Transaction）地址的递增情况==，下图为 Burst 的 3 种编码类型

  • Fixed
    这种突发类型是用来访问同一个位置的，比如清空 FIFO

    • 每次突发传输时都是访问的同一个地址（如果 Length 大于 1 的话）
    • 每次突发传输时有效的字节数都是一样的；只会存在传输时 WSTRB 选通的字节不同
    • 突发长度支持范围是 1 ~ 16

  • Incr
    这种突发类型每次传输时地址都会往上递增。而每次递增的单位取决于该事务的突发大小

    举例：

    假设 AXI 总线的数据位宽为 256bit（32B），在一次 Burst Type = Incr 的事务中（Transaction），定义了 Burst Size = 3’h1 ， Burst Length = 8’h7 ，Burst Address = 32’h0
    那么 AxADDR 的地址将从 32’h0 开始递增，每次的增量为 32’h2 ，直至递增到 32’he

  • Wrap
    这个突发类型跟 Incr 很像，区别是： “如果地址递增到边界上限，则地址不会向上递增了，而是环回到地址的边界下限重新进行递增”
    🔴其余描述：略（暂时没理解应用场景）






Write Strobes

WSTRB 表示==写数据通道中 WDATA 的哪个字节通道是有效的==
每个 bit 都代表着 WDATA 的每个字节，对应关系为：WSTRB[n] 表示 WDATA[n*8 +:8] 字段的数据有效






Response

同样，Response 也存在于读写事务中，用于告知源端当前事务的传输结果
下图只截取了部分含义
主要是其余编码是后面新增的，应用在其他场景中，所以这里暂时不作考虑

  • OKAY
    正常访问成功，数据有效；若是独占访问，则表示事务访问失败
  • EXOKAY
    独占访问成功，表示独占访问的读/写已经完成
  • SLVERR
    Slave error，表示能成功访问 Slave ，但 Slave 希望返回错误情况给 master
  • DECERR
    Decode error，通常由互联组件生成，表示传输的地址中没有 Slave 端





ID

ID 在 AXI 协议中是==为了标识某些需要按序返回的事务==，除了写通道外，每个通道都有 ID（写通道 ID 在 AXI4 中被移除，主要原因是设计开销太大），应用场景可见其他传输特性

ID 在 AXI 总线传输时有以下要求：

  • 对于同一个 ID 的事务来说，需要数据必须按序返回
  • 不同 ID 之间的事务可以 Out of Order（乱序）返回

    比如 Master 端发起了 2 个不同的 ID 事务，在 A 事务返回的期间如果总线空闲，则可以穿插 B 事务返回的数据

    注意：不论是 A 事务还是 B 事务，其事务返回的顺序必须按序






传输机制

基本传输流程

  • 写操作时序

    如上图所示为 AXI-Full 协议中最基本的写操作时序图

    • 在 T2 时刻，Master 端下发写命令，目的是往 32’h0 ~ 32’h7 地址里面写入 8’h0~7，但此时 awready 处于低电平，表示 Slave 端尚未准备好接收写命令，因此需要 Master 端的命令保持不变
    • 在 T3 时刻，awready 变回高电平，并且 awvalid 也为高电平，此时 Slave 端成功接收写命令
    • 在 T4 时刻，Master 端开始连续发送写数据
    • 在 T10 时刻，wready 处于低电平，表示 Slave 端暂时无法接收数据，因此需要 Master 端保持数据不变
    • 在 T11 时刻，wready 变回高电平，Slave 端继续接收数据
    • 在 T12 时刻，wlast 为高电平，表示当前发送的数据为最后一个数据
    • 在 T13 时刻，Slave 端返回 OKAY 给 Master 端，表示写操作已经完成



  • 读操作时序

    如上图所示为 AXI-Full 协议中最基本的读操作时序图

    • 在 T2 时刻，Master 端下发写命令，目的是读取 32’h0 ~ 32’h7 地址里面的数据内容，但此时 arready 处于低电平，表示 Slave 端尚未准备好接收写命令，因此需要 Master 端的命令保持不变
    • 在 T3 时刻，arready 变回高电平，并且 arvalid 也为高电平，此时 Slave 端成功接收读命令
    • 在 T4 时刻，Slave 端开始连续发送写数据，并且每一拍数据的 arresp 都是表示 OKAY
    • 在 T10 时刻，rready 处于低电平，表示 Master 端暂时无法接收数据，因此需要 Slave 端保持数据不变
    • 在 T11 时刻，rready 变回高电平，Master 端继续接收数据
    • 在 T12 时刻，rlast 为高电平，表示当前发送的数据为最后一个数据并且读操作已经完成





其他传输特性

窄传输

窄传输（Narrow Transfers），简单来说就是==要传输的数据位宽比总线位宽小，需要根据地址和控制信息去决定传输的字节通道==
- 当突发类型是 Incr 、Wrap 时，每次传输必须使用不同的字节通道
- 当突发类型是 Fixed 时，每次传输可以使用相同的字节通道

这里容易与 Unaligned Transfer 混淆

  • 窄传输主要关注的是 “数据位宽比总线位宽小，所以需要通过 WSTRB 去使对应的数据有效”
  • 非对齐传输主要关注的是 “地址的起始位置在哪，数据应该与之对应”

非对齐传输

非对齐传输（Unaligned Transfers），简单来说就是 Master 端可以不按照常规的数据位宽对齐地址的要求，随意访问任意地址

通常来说，访问的 AxADDR 应该与 AxSIZE 对齐，也就是 AxADDR 的地址增量应该是 AxSIZE。比如：32bit 位宽的数据传输，地址增量为 0x4，理应 AxADDR[1:0] 应该为 0 ，如果低 2bit 的值不为 0 ，则是非对齐访问；但 AXI 协议允许非对齐传输，则 Master 端可以通过以下 2 种方式进行非对齐传输：

  • 通过地址的低位来表达非对齐地址（即直接访问具体的地址）
  • 使用对齐地址，但通过 WSTRB 去表示非对齐数据的位置（通过数据选通的方式告知其起始位置）

而 Slave 端不能直接依赖 WDATA 去获取数据，而是结合 AWSIZE、AWADDR、AWLEN、WSTRB这些信息一起判断哪些有效的字节数据才是真正传输的数据








Outstanding


Outstanding 简单来说就是==允许请求像流水线一样，在数据未返回之前可以发起下一次请求==。但并不意味着 Master 端可以直接把总线当作 Stream 流去使用，而是由 Outstanding Number 决定该总线上最大能有多少个请求



乱序


Out of Order 是==利用总线的 ID 去给不同的事务打上标识符，让总线可以根据 ID 去乱序处理不同的事务。==

换句话说，不同的事务可能需要花费不同的时间，有些事务处理得很快、有些则很慢，他们之间是没有依赖或顺序关系的（相互独立），因此可以先响应已经处理好的事务，这样就不会出现因为上一个事务还没响应，导致需要一直等待这种情况出现，大大节省响应时间

A 事务的返回时间为 5 cycle
B 事务的返回时间为 1 cycle
C 事务的返回时间为 2 cycle




交织读写


Interleaving，可以理解为更细粒度的乱序（Out of Order），是为了减少读写数据通道中没有利用到的空拍，最大利用通道带宽

🔴但在 AXI4 之后的协议中，只有读通道支持数据交织，写通道不支持，如果写通道也要实现数据交织，则需要更大的面积以及更复杂的控制逻辑，因此在 AXI4 时已经移除了写交织，并且写通道的 WID 也一并被移除
